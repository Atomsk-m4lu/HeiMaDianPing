## 二、已证实的取证结论（字节码 / 配置 / 日志 / SQL）

1. **发送路径两版一致**：`VoucherOrderServiceImpl` 字节码差异仅为“回滚失败落库”try-catch；`RocketMQTemplate.syncSend` 调用与 `send-message-timeout: 10000` 两版完全相同；yaml 差异仅为新增批次配置（rate-limit / mq-event / cache.local）。→ “旧版发送代码更差”不成立。
2. **800 超时 = 10s 客户端超时打满**（`RemotingTooMuchRequestException: sendDefaultImpl call timeout`）。
3. **口径漂移实锤（SQL 双证）**：800 条 `rollback triggered` 回滚记录对应的订单，其创建时间全部晚于回滚时间（`fail_then_order_born = 800`）→ 被回滚用户最终仍拿到订单。
4. **语义冲突点（两版同构，设计风险点）**：『发送失败 → Redis 回滚 + 提示用户重试』与『本地消息表重试 → 最终补发建单』并存——用户被回滚后订单仍被补建，且库存已回补。建议与设计意图核对（是否需要：回滚时同步作废重试记录，或改为“处理中”提示而非“请重试”）。**不修改代码，仅记录。**
